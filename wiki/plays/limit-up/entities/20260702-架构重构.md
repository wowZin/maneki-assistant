# 20260702 打板玩法架构重构

## 动机

前一日集中优化后，打板玩法内堆积了大量版本化的复合总分与回测脚本：`new_total_v2 / balanced_total / balanced_total_v2 / sentiment_adaptive_total / ultimate_total_v1~v5 / cpt_amount_percentile / balanced_ensemble / sentiment_position_combo_pit` 等十余个总分并存于 pipeline，代码稳健性无法保证。用户判断当前效果虽然优于原打板策略，但要求一次彻底重构：去版本化、多维度架构保留、因子下沉、真实调用单测覆盖、审计红线、wiki 数据路径规范化。

## 关键变化

### 1. 唯一总分 `total_score`（去版本化）

- **入口**：`plays/limit_up/total.py::total_score(row) -> float`
- **公式**：`0.4 * sentiment_amount_boosted + 0.5 * sentiment_position_combo + 0.7 * sentiment_volatility_combo`
- **公式**：sentiment 维度三组件加权（amount_boosted 0.4 + position_combo 0.5 + volatility_combo 0.7）；权重待训练集重优化
- **删除**：所有 v* / balanced / adaptive / ensemble / conditional / cpt_* 复合总分

### 2. 多维度架构保留 + 因子下沉

- 五个维度评分模块 `strategies/{fundamental,technical,fundflow,sentiment,shortterm}.py` 对外契约不变
- 有效因子从 `backtest/factor_lib.py`（原 2900 行）迁到 `factors/<dim>/*.py`，去 `_pit / _v*` 后缀
- 概念/龙虎榜类因子（NaN-IC，面板缺列）暂存 `factors/_deprecated/`，等 `enrich_panel` 补齐后再重启
- 负 IC 单因子（`volatility_contraction / large_amplitude_risk / sentiment_contrarian` 等）直接删除

### 3. Pipeline 拆分

`pipeline.py` 从 1823 行精简到 <300 行，拆分为：

| 模块 | 职责 |
|------|------|
| `scanner.py` | 候选股扫描（THS 热榜 / from-file） |
| `filter.py` | 7 规则过滤（保持） |
| `pre_rank.py` | 涨速+涨幅+人气预排序 |
| `cache_layer.py` | 同日 analysis 缓存（wiki/raw → data 回落） |
| `quote_cache.py` | THS/Tushare/jvquant 批量预取 |
| `scoring.py` | 五维度并行打分 |
| `total.py` | 唯一总分聚合 |
| `push.py` | 飞书卡片 + pushed/ 落盘 |
| `pipeline.py` | 编排（仅） |

### 4. backtest 收敛为三件套

原 20+ 脚本（validate*.py, optimize*.py, mine*.py, enrich*.py, evaluate*.py, topk_backtest.py, train_walkforward.py, ...）合并为：

- `backtest/mine.py` — 因子挖掘
- `backtest/validate.py` — IC 与 hit 报告
- `backtest/optimize.py` — 权重优化

### 5. 数据源审计（红线）

- `scripts/jvquant_client.py` 与 `jvquant_ws_client.py` 补齐 `audit.record` 埋点
- 错误统一结构化 `extra`：`ERR:<异常类>|<msg60>|params:<key>`
- `audit.summary()` 按 api 拆分；新增 `dump(path)` 供 pipeline 结束时落 `data/logs/audit_{trade_date}.log`

### 6. wiki/raw 目录分层与搬迁语义

**Before**：`wiki/raw/{signals,analysis,pushed,reports,weights}/` 扁平结构，玩法 `data/` 复制到 `wiki/raw/` 后原文件不删。

**After**：

```
wiki/raw/
├── articles/           # 跨玩法通用
├── concepts/           # 跨玩法通用（预留）
├── history/            # 跨玩法通用
├── limit-up/           # 打板玩法归档
│   ├── signals/ analysis/ pushed/ reports/ weights/
└── watchdog/           # 其他玩法（未来）
```

- `wiki/compile.py::_sync_raw_data` → `_relocate_raw_data`，语义从 copy 改为 **move**
- 玩法 `data/` 是运行时可写工作区，收盘 compile 后当日文件消失
- 下游读者（`review.py`, `health_patrol.py`, `cache_layer.py`, `backtest/data.py`）加 `wiki/raw/limit-up/ → data/` 回落顺序

### 7. 单测红线

- `plays/limit_up/tests/conftest.py::pytest_configure` 检查 `TUSHARE_TOKEN / THS_COOKIE / JVQUANT_TOKEN`
- 缺任一环境变量 → 抛 `RuntimeError`，测试直接 fail（不 skip）
- 所有因子/维度/pipeline/数据源单测**真实调用**，禁止 mock
